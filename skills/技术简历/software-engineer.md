# Software Engineer Resume Skill

> Optimized resume for software engineering roles at all levels.

## When to Use

- Applying to software engineering positions (SWE, SDE, Backend, Frontend, Full-stack)
- Targeting FAANG, startups, or mid-size tech companies
- Career fairs, referrals, or direct applications
- When the job posting lists specific technical requirements

## Framework

### Software Engineer Resume Structure

1. **Header** — Name, email, phone, LinkedIn, GitHub, personal site
2. **Summary** (optional, for senior+) — 2-3 lines highlighting specialization
3. **Technical Skills** — Grouped by category
4. **Experience** — Reverse chronological with project-focused bullets
5. **Projects** — Personal/open-source projects (especially for junior engineers)
6. **Education** — Degree, school, year, relevant coursework

### Technical Skills Section

```
TECHNICAL SKILLS
Languages:      [Language 1], [Language 2], [Language 3]
Frontend:       [Framework 1], [Framework 2], [Library 1]
Backend:        [Framework 1], [Framework 2], [Tool 1]
Databases:      [DB 1], [DB 2], [DB 3]
Cloud/Infra:    [Provider], [Container tool], [CI/CD tool]
Tools:          [Version control], [Monitoring], [Project management]
```

### Bullet Point Formula for Engineers

```
[Action Verb] + [Technical Implementation] + [Scale/Metric] + [Business Impact]
```

## Examples

### Before & After: Project Description

**Before (junior-level mistake):**
```
Project: Task Manager App
- Used React and Node.js
- Implemented CRUD operations
- Used MongoDB for database
- Added user authentication
```

**After (impact-focused):**
```
TaskFlow — Collaborative Task Management Platform     React, Node.js, MongoDB | github.com/you/taskflow
• Built real-time task sync using WebSocket connections, supporting
  concurrent editing by 50+ users with sub-100ms update propagation
• Implemented JWT authentication with refresh token rotation and role-based
  access control (admin, manager, member)
• Designed MongoDB schema with compound indexes, optimizing query performance
  from 800ms to 45ms for common search operations
• Deployed on AWS with Docker, handling 5K daily active users with 99.8% uptime
```

### Before & After: Senior Engineer Achievement

**Before:**
```
- Led the team to improve performance
- Worked on the migration project
- Helped with hiring
```

**After:**
```
• Led performance optimization initiative across 3 microservices, reducing
  p99 latency from 1200ms to 180ms through database query optimization,
  caching layer implementation, and async processing — improving conversion
  rates by 12% ($2.4M annual revenue impact)

• Designed and executed migration of monolithic payment service to 5
  microservices, coordinating with 4 teams over 6 months. Achieved zero
  downtime during migration and reduced deployment cycle from bi-weekly
  to multiple daily releases.

• Built engineering hiring pipeline including structured interviews, take-home
  rubrics, and technical phone screens — growing the team from 8 to 22
  engineers while maintaining a 4.2/5 candidate experience score.
```

### STAR Method for Technical Achievements

```
SITUATION:  Our main API was experiencing [problem] at [scale]
TASK:       I needed to [technical objective] while [constraints]
ACTION:     I [technical approach with specific tools/technologies]
RESULT:     This led to [quantified improvement] impacting [business metric]
```

## Common Mistakes

1. **Listing technologies without context** — "React, Node.js" is not an achievement
2. **No metrics** — Include latency, throughput, uptime, cost savings, user counts
3. **Too many projects** — 3-5 strong bullets beat 15 weak ones
4. **Forgetting soft skills at senior+** — Leadership and mentorship matter
5. **Buzzword stuffing** — "AI-powered blockchain cloud-native" — be specific
6. **Missing GitHub** — For engineers, a GitHub profile is expected
7. **Not explaining scale** — "Built an API" vs "Built an API serving 10M requests/day"
8. **Including every technology ever touched** — List what you're proficient in

## 中文版本

### 适用场景

- 申请软件工程师岗位（后端、前端、全栈）
- 目标公司：BAT、字节、美团等互联网公司，或外企
- 校招、社招、内推

### 中文技术简历要点

- **篇幅**：社招1-2页，校招1页
- **技术栈**：分语言、框架、工具三类列出
- **项目描述**：背景 → 职责 → 技术方案 → 成果
- **量化指标**：QPS、响应时间、可用性、节省成本

### 互联网公司简历特点

- 阿里：重视业务理解和数据驱动
- 字节：看重创新和快速迭代能力
- 腾讯：关注产品思维和用户体验
- 美团：强调系统设计和业务复杂度

### 校招特别注意

- 实习经历放在教育经历之后
- 课程设计和大作业可以作为项目经历
- ACM/OI获奖经历很重要
- 论文发表是加分项
